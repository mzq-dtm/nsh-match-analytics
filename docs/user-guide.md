# 用户使用指南

本文面向查看联赛数据、导出团队战报、分析出勤和配置联赛团队的普通用户。管理员如需上传比赛数据，请阅读[管理员导入指南](admin-import.md)。

系统对经典服联赛与黄金畅玩服联赛提供相同的查询和分析入口。页面包含“联赛数据”“帮众出勤分析”“帮众数据查询”“联赛团队配置”和“使用帮助”五个栏目。表格较宽，团队配置还需要拖放操作，建议使用桌面浏览器。

## 1. 联赛数据

### 1.1 选择比赛

打开“联赛数据”，从“选择联赛”下拉框选择一场比赛。页面随后显示：

- 对阵双方与比赛时间；
- 本帮的胜负结果，未填写时显示“结果未录入”；
- 管理员录入的比赛备注；
- 本帮参赛数据，默认先显示“全帮数据”。

每次重新选择比赛都会回到本帮视图。页面提供以下数据范围：

- “全帮数据”：本场当前一方的全部参赛记录；
- “团总数据”：按团长汇总人数、战力和战斗指标；
- “职业总数据”：按职业汇总人数，并显示各项人均指标；
- 各团标签：查看某一团的全部成员，还可以继续按职业筛选；
- 各职业标签：查看某一职业的全部成员，还可以继续按团长筛选。

这里的“一人”指 CSV 中的一条本场参赛记录。团与职业的总人数、总值或平均值也以这些记录为基础。

### 1.2 本帮与对手数据

点击“显示对手数据”可切换到对手视图，再点击“显示本帮数据”即可返回。本帮和对手视图都会根据当前一方的数据重新生成全帮、团和职业标签。

两类数据的用途不同：

- 本帮玩家使用稳定的玩家 ID 关联昵称历史和历场表现，因此可以从玩家 ID 或昵称进入个人历史；
- 对手玩家仅保存当场快照，没有可跨场关联的稳定玩家 ID，也没有装备评分、技能评分、修炼和总战力，因而不能进入个人历史，页面也不会提供这些明细列。

因此，对手汇总表中与战力有关的空值或 `0` 不代表对手的真实战力，不应据此比较双方实力。

### 1.3 敌我统计对比

选择比赛后点击“敌我统计对比”，可以在同一窗口查看双方的：

- 联赛人数；
- 总对玩家伤害、总对建筑伤害和总击杀；
- KD；
- 总治疗、总化羽、总青灯焚骨、总控制和总战备资源。

每项指标下方的数据条以该项数值较高的一方为 100% 进行相对缩放，只用于快速比较长度，不是固定量程。数值本身才是精确结果。本帮名称旁还会显示本帮参赛记录的总战力；由于对手快照不含战力，对手侧不显示总战力。

### 1.4 明细表交互

联赛明细表支持以下操作：

- 排序：左键点击表头，按该列排序；再次点击可切换升序和降序。切换团或职业后，当前排序仍会应用到筛选后的记录。
- 列显隐：勾选或取消表格上方的字段。默认隐藏玩家 ID、等级、装备评分、技能评分、修炼和“单次击杀所用伤害”等部分字段；本帮与对手分别维护可见列。
- 数据条：战斗指标单元格中的色条按当前明细范围内的最大值缩放。切换全帮、团、职业或嵌套标签后，色条长度会重新计算，所以它适合比较当前表格中的相对大小，不能跨视图直接比较。
- 高亮列：右键点击表头，再次右键可取消。
- 高亮行：右键点击该行最左侧的“序号”单元格，再次右键可取消。
- 高亮单元格：右键点击任意数据单元格，再次右键可取消。
- 清除标记：点击页面上方的“清除标记”，一次清除所有行、列和单元格标记。
- 查看历史：在本帮明细中左键点击玩家 ID 或昵称，跳转到该玩家的历史数据。对手明细不支持此操作。

团总数据和职业总数据也可以点击表头排序，但列显隐、数据条和右键高亮仅用于明细表。

### 1.5 自动分析

“自动分析”始终分析所选比赛的本帮数据，即使当前正在查看对手数据也不会改变分析对象。它用于快速找出多项核心指标同时偏低的记录，不等同于对玩家表现的完整评价。

阈值使用最近秩百分位法计算：将同一取值范围内的数据从小到大排列，25% 分位数取第 `ceil(人数 × 25%)` 个值。指标等于阈值视为达到阈值，只有严格低于阈值才算该项未达到。

各职业的考察口径如下：

| 职业 | 考察指标 | 阈值来源 |
| --- | --- | --- |
| 素问 | 治疗量 | 本场所有素问治疗量的 25% 分位数，再乘以 50% |
| 九灵 | 击败、对玩家伤害、对建筑伤害、青灯焚骨 | 前三项使用本场所有非素问玩家的 25% 分位数；青灯焚骨使用本场所有九灵的 25% 分位数 |
| 铁衣 | 击败、对玩家伤害、对建筑伤害、控制 | 前三项使用本场所有非素问玩家的 25% 分位数；控制使用本场所有铁衣的 25% 分位数 |
| 其他职业 | 击败、对玩家伤害、对建筑伤害 | 本场所有非素问玩家的 25% 分位数 |

只有当一名玩家的全部考察指标都严格低于各自阈值时，才会出现在自动分析结果中。只要任一考察指标达到阈值，该玩家就不会被列出。

眼位、资源位、连枝鸿等功能位的职责不一定体现在这些指标中，可能被误判。自动分析结果应结合指挥安排、职业职责、临场任务和原始录像判断，不宜单独作为奖惩依据。

### 1.6 导出分团数据

选择一场比赛后，先确认明细表、胜负和备注已经更新为该场比赛，再点击页面上方的“导出分团数据”。浏览器会生成本帮的团队战报 PNG 长图并直接下载。快速连续切换比赛时不要立即导出；按钮显示“正在生成……”时请等待当前任务结束，不要重复点击。

导出功能读取页面已经加载的本帮数据。当前比赛加载完成后，即使页面显示的是对手数据，导出的仍然是本帮战报。页面当前所在的全帮、团或职业标签，以及明细表的排序、列显隐、数据条范围和右键高亮，也都不会改变导出内容。

长图顶部包含对阵双方、比赛时间、本帮结果和比赛备注。后续按团队依次绘制，排序规则为：

1. 有明确团长的团队按参赛人数降序排列；
2. 人数相同时，按团长昵称采用中文自然顺序稳定排列；
3. 团长为空或标记为“无”的记录归入“未分团”，并始终放在最后。

每个团队的标题显示团长昵称和参赛人数，并固定包含以下四张表。即使某张表没有符合条件的记录，也会保留空表及相应提示。

| 表格 | 纳入记录 | 排序方式 |
| --- | --- | --- |
| 对玩家伤害表 | 本团全部非素问记录 | 对玩家伤害降序 |
| 对建筑伤害表 | 本团全部非素问记录 | 对建筑伤害降序 |
| 击杀数表 | 本团全部非素问记录 | 击败降序 |
| 治疗量表 | 本团全部素问记录 | 治疗值降序 |

排序指标相同时按玩家昵称采用中文自然顺序稳定排列；昵称也完全相同时保留原始数据顺序。因此，同一名非素问玩家会出现在前三张表中，但在三张表里的位置可能不同；素问只进入治疗量表。

四张表都使用以下固定 18 列：序号、昵称、职业、所在团长、总战力、KD、总伤害、击败、助攻、对玩家伤害、对建筑伤害、承受伤害、重伤、治疗值、化羽、青灯焚骨、控制和战备资源。导出不会加入玩家 ID、等级、装备评分、技能评分、修炼或单次击杀所用伤害，也不会跟随页面上的列显隐设置。

每张表会分别计算每个数据条字段的最大值，并以该表该字段的最大值作为数据条的 100%。数据条适合比较同一张表、同一字段内的相对大小，不能用长度跨表比较；表格标题注明的排序字段还会使用更明显的表头和边框。

下载文件名通常为：

```text
原比赛文件名（移除末尾 .csv）_团队战报.png
```

文件名中的操作系统保留字符会被替换。导出没有预览步骤，也不会把生成的图片上传或保存到服务器：数据整理、Canvas 绘制和 PNG 编码都在当前浏览器中完成。

战报包含玩家昵称、战斗数据、比赛结果和备注，请按帮会内部资料妥善保存和分享。长图的高度会随团队和参赛人数增加，生成时可能占用较多内存；不同浏览器和设备对 Canvas 的尺寸、面积和可用内存限制也不同。建议使用桌面版 Chrome、Edge 或 Firefox。手机、较旧的浏览器或超大场次可能下载失败或显示生成错误，严重时标签页可能失去响应；当前版本不会改为上传服务器生成。

### 1.7 常用指标口径

| 指标 | 计算方式 |
| --- | --- |
| 总伤害 | 对玩家伤害 + 对建筑伤害 |
| KD | 击败 ÷ `max(重伤, 1)` |
| 单次击杀所用伤害 | 对玩家伤害 ÷ `max(击败, 1)`；个人明细向下取整，团汇总显示为零位小数 |
| 团 KD | 团总击败 ÷ `max(团总重伤, 1)` |
| 团平均总战力 | 团成员总战力之和 ÷ 团总人数 |
| 职业人均指标 | 该职业对应指标总和 ÷ 该职业总人数 |

KD 和单次击杀所用伤害使用 `max(实际值, 1)` 作为分母，以避免除以零。没有击败或重伤时，相关比值应结合原始数值一起理解。

## 2. 帮众出勤分析

打开“帮众出勤分析”后，页面默认使用数据库中最早一场比赛的日期作为开始日期，并预填当前日期后自动加载结果。请先核对预填结束日期，尤其是在本地凌晨使用页面时；修改日期后点击“刷新”重新统计。开始和结束日期都包含在统计区间内。

出勤率的口径为：

```text
出勤率 = 玩家在所选日期区间内有本帮参赛记录的场数 ÷ 区间内已录入的全部比赛场数
```

例如，区间内录入了 8 场比赛，某玩家有 6 场本帮参赛记录，则显示 `6 / 8 (75%)`。页面不会显示区间内出勤次数为 0 的玩家，也不会把对手记录计入本帮玩家出勤。

表格中的数据范围需要特别注意：

- 总对玩家伤害、总对建筑伤害、总击杀、总治疗、总控制和总青灯焚骨，仅累计所选日期区间内的数据；
- 总 KD 为区间内总击杀除以 `max(区间内总重伤, 1)`，不是各场 KD 的平均值；
- 总战力取该玩家在整个数据库中最近一次出场时的总战力，不受所选日期区间限制；
- 首次联赛时间和最后联赛时间取该玩家在整个数据库中的首次、最后一次出场，也不受所选日期区间限制；
- 历史昵称会先按玩家去重，再按各昵称第一次出现的时间从旧到新展示；同一昵称中断后再次启用，也只显示一次。

点击任意表头可排序，再次点击切换方向。点击玩家 ID 或历史昵称可进入该玩家的完整历史。伤害或治疗达到一万时，页面可能以截断后的整数“万”显示，但排序仍使用原始数值。

如果所选区间没有已录入的比赛，表格为空。

## 3. 帮众数据查询

“帮众数据查询”按数据库中的玩家 ID 展示本帮玩家的全部已录入历史。玩家改名后，如果新旧昵称记录使用同一玩家 ID，这些昵称下的比赛会继续关联到同一个人；如果记录使用另一个玩家 ID，则会作为两个玩家分别展示。对手的单场快照不会出现在这里。

### 3.1 搜索玩家

搜索框支持：

- 系统返回的最近使用过的三个不重复昵称；
- 中文昵称的无声调全拼；
- 中文昵称的拼音首字母；
- 玩家 ID；
- 用空格分隔的多个关键词。

多个关键词采用“同时满足”的方式匹配。例如，一个关键词匹配昵称，另一个关键词匹配 ID 时，只保留同时包含两者的候选人。候选列表最多展示该玩家最近使用过的三个不重复昵称和玩家 ID。昵称来自该玩家的全部历史，不要求在查询时仍然有效；如果同一昵称曾被确认给不同玩家 ID，候选列表可能出现两个同名项，应结合玩家 ID 和比赛历史判断。可以用鼠标选择，也可以用上下方向键移动、Enter 确认、Esc 关闭列表。

从“联赛数据”或“帮众出勤分析”点击本帮玩家，也会直接打开该玩家的历史页面。

### 3.2 阅读历史表

历史表默认包含全部已录入比赛，并保留玩家当场的昵称、职业、所在团长、战力属性和战斗指标。表格上方可以控制列的显示与隐藏；装备评分、技能评分、修炼、助攻和战备资源默认隐藏。

左键点击表头可按该列排序，再次点击切换方向。表中的击败、对玩家伤害、对建筑伤害、总伤害和治疗排名，范围都是该场比赛的全部本帮参赛记录，不区分团队或职业。排名计算为“数值严格高于该玩家的人数 + 1”，所以数值相同的玩家并列，例如可能出现 `1、1、3`。

### 3.3 合服后的身份与历史

合服时，管理员可能会为昵称设置新的身份确认边界。这个处理不会删除旧比赛或历史昵称，但会结束原先开放的昵称映射；随后由管理员在新比赛导入时逐人核验并填写合服后实际使用的游戏玩家 ID。

- 合服后的实际游戏 ID 与旧 ID 相同时，合服前后的比赛继续显示在同一份玩家历史和同一行出勤统计中；重复启用的同名昵称只展示一次。
- 合服后的实际游戏 ID 已变化时，系统会按新旧两个 ID 分别展示记录，不会为了保持连续而自动合并历史；同一昵称也可能出现在两个玩家候选项中。此时应以玩家 ID 和具体比赛记录判断身份，不能只看昵称。
- 玩家候选列表读取全部昵称历史，因此在身份边界后的空窗期仍可通过历史昵称或玩家 ID 查看旧比赛；依赖“当前有效昵称”的功能则可能暂时找不到该成员。
- 只有在合服后成功导入的比赛中作为本帮参赛玩家或团长出现的昵称，才会从该场比赛时间起恢复为当前有效。尚未出现的成员，其旧战绩仍然保留，但当前昵称匹配要等以后出场并完成身份确认。

## 4. 联赛团队配置

“联赛团队配置”用于在浏览器中编排本帮五个团队。它不会修改数据库中的联赛记录，也不会替代管理员导入流程。

### 4.1 准备成员 CSV

上传文件必须使用小写 `.csv` 扩展名，建议保存为 UTF-8 编码。至少需要以下三个表头，名称必须完全一致：

```csv
名称,职业,总战力
玩家甲,铁衣,180000
玩家乙,素问,175000
```

可以包含其他列，但页面只读取“名称”“职业”“总战力”。为避免解析或操作异常，还应满足：

- 使用英文半角逗号分隔；
- 每行一名成员，名称保持唯一且不为空；
- 名称和职业中不要包含逗号或换行；当前页面不支持带引号的复杂 CSV 字段；
- 总战力填写非负整数，不要使用逗号、单位或其他格式化字符。
- 职业建议使用系统当前支持的精确名称：血河、铁衣、素问、九灵、神相、碎梦、龙吟、玄机、鸿音、荒羽、潮光、沧澜、云瑶、瑶光、修罗。

未知或拼写错误的职业仍可能在“全体成员”视图中出现，但不会获得正确职业颜色，也不会进入独立职业筛选或全局职业分布；右键职业菜单也只提供上述固定职业。发现异常时应先修正 CSV 或在页面中改为正确职业。

这个成员 CSV 只供团队配置使用，与管理员导入比赛所需文件不是同一份格式。管理员文件的要求见[管理员导入指南](admin-import.md)。

### 4.2 筛选和查看成员

上传成功后，所有成员按总战力从高到低进入“替补席”。左侧职业勾选和最低评分只会筛选替补席当前显示的成员，不会删除成员，也不会改变已经分入团队的成员。

将鼠标悬停在成员上，可查看系统按当前昵称找到的最近三场联赛记录，包括当场团队、击杀、KD、伤害、治疗及团内排名。如果昵称无法与系统中的当前有效昵称精确匹配，则显示“未找到历史数据”。这里的排名是在玩家当场所在团内计算，与“帮众数据查询”中的全帮排名范围不同。

合服身份边界建立后，到该昵称在合服后比赛中重新登记之前，团队配置会把它视为没有当前有效映射并显示“未找到历史数据”。第一次比赛导入后也只会恢复本场出现过的参赛玩家和团长；未出场成员仍可能暂时没有悬停历史。这不表示旧战绩已被删除，可以到“帮众数据查询”中按玩家 ID 核对。

将鼠标悬停在某团标题上，可以查看该团的职业分布。标题同时显示当前人数、30 人上限和平均总战力。

### 4.3 编排五个团队

页面固定提供一团至五团，每团最多 30 人，总容量最多 150 人：

- 从替补席将成员拖到目标团队；
- 在两个团队之间直接拖动成员；
- 将团队成员拖回替补席；
- 目标团已有 30 人时，拖入操作不会生效；
- 点击某团的“清空”，把该团全部成员送回替补席；
- 点击“重置”，清空五个团队并把全部成员送回替补席；
- 右键点击替补席或团队中的成员，从菜单中修正职业。相同名称在页面各处的职业会同步更新。

拖入团队后，成员会按职业名称排序。页面不会自动均衡人数、战力或职业，需要配置者自行判断。

### 4.4 导出结果

- “保存表格”会直接下载 `分团配置.xlsx`。文件只包含一团至五团中已分配成员的名称和职业，不包含替补席、总战力或历史数据。
- “保存图片”实际只是在页面中生成并打开图片预览，不会自动下载文件。预览包含五团标题、人数、平均总战力，以及已分配成员的名称、职业和总战力。需要保留时，请使用浏览器的“图片另存为”、复制图片或截图功能。

### 4.5 本地缓存和隐私

团队配置会缓存在当前网站、当前浏览器配置文件的 `localStorage` 中，缓存内容包括成员名称、职业、总战力、替补席与五团分配、筛选条件，以及为悬停提示取得的近期历史。页面离开、隐藏或关闭时会尝试保存，重新打开同一网站时会尝试恢复。

缓存按浏览器本地时间以星期日 00:00 为每周边界。缓存时间早于本周星期日 00:00 时，会在下次打开团队配置页面时被判定为过期并删除。它不是服务器备份，也不保证在无痕模式、清理网站数据、浏览器策略限制或更换设备后仍然存在。

成员 CSV 的三个字段由浏览器读取；为了查询近期历史，成员名称列表会发送到本系统的查询服务。请只在可信设备和可信部署地址上处理成员名单。共用电脑使用完毕后，应清除该网站的数据；这会同时删除未导出的团队配置。导出的电子表格和手动保存的图片也包含成员信息，请按帮会内部资料妥善保存和分享。

## 5. 常见问题

### 为什么联赛列表为空，或缺少某场比赛？

页面只显示已经由管理员成功写入数据库的比赛。请先确认选择框中是否有记录，再联系管理员核对导入状态。管理员可参考[管理员导入指南](admin-import.md)。

### 为什么对手没有玩家 ID、战力或历史？

对手数据按单场快照保存，没有跨场稳定身份，也不包含成员表中的战力属性，因此不能查询个人历史。对手汇总中的战力空值或 `0` 也不能视为真实战力。

### 为什么正在查看对手数据，导出的却是本帮战报？

“导出分团数据”的设计对象固定为本帮。当前显示本帮还是对手，只影响页面查看，不改变导出对象。如果需要核对双方总量，请使用“敌我统计对比”。

### 为什么导出长图的顺序或列与当前页面不同？

长图使用独立且固定的导出版式，不读取页面当前的标签、筛选、排序、列显隐或高亮状态。团队按人数降序排列，每团四张表分别按指定指标重新排序，并始终使用固定 18 列。

### 为什么同一名玩家在长图中出现多次，或某张表是空的？

同一名非素问玩家会分别进入对玩家伤害、对建筑伤害和击杀三张排名表；素问只进入治疗量表。某团没有对应职业类型时仍会保留空表，便于不同团队使用一致版式。

### 为什么点击“导出分团数据”后没有下载，或提示生成失败？

先确认已经选择比赛，并且明细表、胜负和备注都已更新为该场比赛，再重新导出；快速连续切换比赛后应等待页面稳定，同时检查浏览器是否拦截了下载。战报完全依赖当前浏览器的 Canvas 和可用内存；如果图片过长或设备资源不足，请改用桌面版 Chrome、Edge 或 Firefox，关闭占用内存较多的页面后重试。超出浏览器尺寸或面积上限的单场数据，当前版本无法在服务器端继续生成。

### 为什么数据条在切换团队或职业后长度变了？

数据条以当前明细表中该指标的最大值为 100% 重新缩放。切换筛选范围后参照值会变化，这是正常现象。

导出长图的数据条也使用相对量程，但每张表、每个带数据条的字段分别计算最大值。因此只能比较同一张导出表中同一字段的数据条，不能跨表比较长度。

### 为什么自动分析列出了功能位玩家？

自动分析只根据固定战斗指标和本场分位数筛选，不知道玩家承担的眼位、资源位、连枝鸿等临场职责。请结合指挥安排和录像复核。

### 为什么出勤表里没有从未出勤的玩家？

页面会过滤所选区间内出勤次数为 0 的玩家。分母仍是区间内全部已录入比赛场数。

### 为什么调整了出勤日期，总战力、首次或最后联赛时间没有变化？

这三项读取玩家全库范围的最近战力、首次出场和最后出场；只有累计战斗指标与出勤场数受日期区间限制。

### 为什么最近使用过的昵称可以找到同一个玩家？

本帮历史以数据库中的玩家 ID 关联。候选列表会返回最近使用过的三个不重复昵称；只要这些昵称记录使用同一玩家 ID，选择其中任一昵称后，不同时间的比赛记录就归属于同一个玩家。合服后的实际游戏 ID 如果已经变化，系统会按新旧 ID 分别展示，不会只凭昵称或为了保持连续而自动合并历史。

### 为什么合服后团队配置暂时找不到历史？

合服身份边界会结束旧的当前昵称映射。团队配置按当前有效昵称查询，因此一个昵称只有在合服后的比赛中作为本帮参赛玩家或团长出现并完成身份确认后，才会重新取得悬停历史。尚未重新登记时显示“未找到历史数据”不代表旧比赛被删除；可在“帮众数据查询”中按历史昵称和玩家 ID 查找。

### 为什么同一昵称出现了多个玩家 ID？

昵称可以在不同时间属于不同玩家。合服后的实际游戏 ID 已变化，或换人核验得到另一个玩家 ID 时，候选列表和出勤数据会按 ID 分开保留两份历史。请核对玩家 ID、参赛时间和具体比赛，不要只凭昵称选择；发现身份确认错误时应立即联系管理员停止后续导入并按备份恢复流程处理。

### 为什么团队配置 CSV 无法读取？

请确认文件扩展名为小写 `.csv`，编码为 UTF-8，表头准确包含“名称、职业、总战力”，并使用简单的英文半角逗号分隔格式。字段中不要放入逗号或换行。

### 为什么成员拖不进某个团队？

每团上限为 30 人。目标团达到上限后，需要先移出一名成员或点击“清空”。桌面浏览器更适合拖放操作。

### 为什么点击“保存图片”没有下载文件？

该按钮当前只生成图片预览。请在预览中使用浏览器的图片保存功能，或复制、截图后另行保存。

### 为什么星期日打开页面后，之前的团队配置消失了？

团队配置缓存以星期日 00:00 为每周边界，上一周的缓存会在本周首次打开页面时删除。浏览器清理网站数据、使用无痕模式或更换设备也会导致缓存不可用；重要配置请提前导出表格或保存图片。
